THETA.Home.Hatch

ホームを、アプリの棚から
「必要な場所への入口」に変える。

Z Fold5を最初の対象に、ファイルとフォルダを主役にしたAndroidホームアプリ。端のタブから作業場所が滑り出し、閉じると静かな余白に戻る。名前は今回の提案用の仮称。

動くモックアップを開く →

今回の成果物は操作感を確かめるHTMLプロトタイプです。予定・人物・メール・ファイルはすべてサンプル。Androidのホーム設定、端末データの読み出し、送信、ダウンロード、インストールは行いません。

Captureを追加 — モック第3版

閉じたホームと開いたファイラーの同じ場所に、録音・撮影・手書きの3ボタンを配置。アプリを探す前に、思いついたことを残す入口とする。

  • 録音：タップで録音開始・停止の表示デモ、長押しで録音データ一覧。録音中は経過時間と停止を常時表示。見本はRecordingsからも辿れる。
  • 撮影：タップで写真モード、上へ押し出して離すと写真モード、下なら動画モード。長押しで写真・動画のサムネイル一覧。シャッターと録画開始・停止はデモ。見本はCameraに集まる。
  • 手書き：その場でキャンバスを開き、試し書きできる。戻す・クリア・ペン優先の切り替えと、Handwritingへの保存見本。描画はこの表示中だけ保持し、実ファイルとして書き出してはいない。

長押しは約0.56秒、上下ジェスチャーは約38pxを基準にしたモック上の設定。履歴への明示ボタン、カメラ内の写真／動画切り替えも用意し、ジェスチャーだけに依存しない。指を大きく横に動かした操作はキャンセル扱い。

録音・撮影でマイクやカメラは使用しない。Sペンの筆圧・手のひら除外・遅延はAndroid実機で検証する。独立した手書きアプリ（仮称THETA.Ink.Hatch）にし、ホームから即起動・ファイル共有する構成も候補。ジェスチャー判定12ケースとJavaScript構文を確認。ブラウザー表示・Android実機の確認は未完了。

どう使うか

ホーム → 端の「仕事」 → フォルダ → ファイル → 開く・共有

常時置くのは時刻、日付、次の予定、少数の入口だけ。フォルダ、予定、ウィジェット、ブックマーク、アプリは必要なときだけ表示する。「フォルダ」はアプリをまとめた入れ物ではなく、端末内の実フォルダを意味する。

  • Folder Hatch：タブごとに作業フォルダを割り当て。階層を辿り、ファイルを選択。広い画面では一覧とプレビューを並べる。非対応形式はファイル名・種別を表示し外部アプリで開く。
  • Today Hatch：カレンダーへの入口。まず外部アプリ起動と提供元Widgetを使う。独自の予定表示は権限と同期仕様を決めて追加。
  • People Hatch：連絡先・メール・LINEへ短い経路で移動。ファイルの共有先にもなる。
  • Widget Hatch：提供元アプリが公開するAndroidウィジェットをドロワー内に収納。提供されていない画面を自由に埋め込めるわけではない。
  • Tools Hatch：名前で辿れるアプリ一覧、ブックマーク、THETAシリーズの入口。

Foldの開閉で役割を変える — モック第2版

閉じたホーム：時計・フォトフレーム・インジケーター・音楽・よく使うアプリ。設定から各表示モジュールを選べる。開いたホーム：折りたためるフォルダツリー、ファイル一覧、プレビューを中心にした作業面。開閉しても選択中のファイルを保持する操作見本。

Terminal：JARVIS風の静かなシアンの操作盤。Instrument：M.P.Cを参考にした、クリーム色と黒いパッドの機材風。どちらもアプリ名とタブ名を表示する。

モノクロ／反転モノクロ／比較用カラーの切り替え、アプリごとの絵柄変更、アプリとは独立したスタック表紙の設定を追加。右側の10タブは上下スクロールと矢印ボタンで辿る。写真・音楽・ファイル・通信状態はサンプルで、端末には接続していない。アイコンパックや任意画像によるアイコン指定はAndroid実装時の対象で、このモックでは用意した線画を選ぶ。

今回の希望との対応

外観はM.P.C、仕事へのつながりは4本目、全画面を貫く統一感は3本目、すぐ呼び出せる道具は1本目が参考になる。これは各動画の優劣の採点ではなく、今回の要件に対する設計上の評価。

最大の追加要件は「アプリを分類するフォルダー」から「実際の文書や画像が入ったフォルダ」への拡張。今回確認した主要場面では、実フォルダを画面端のタブに結びつけ、階層を辿ってファイルを開く体験は確認できなかった。各アプリにその機能が絶対にないと断定するものではない。

モックへの設計提案

  1. Quiet案を軸に、画面の中央は静かに保つ。ファイルへの入口は文字付きタブにする。
  2. タブを「アプリの種類」だけでなく「仕事」「個人」「資料」といった作業場所にも割り当てる。関連するフォルダ、予定、リンク、Hatchへの入口を同じ場所に集める。
  3. Foldを閉じたら一覧に集中し、開いたらファイルの内容を横に出す。同じフォルダ・選択を保持して、作業の続きを引き継ぐ。
  4. 既存Hatchを開く・共有で渡す・未導入時に配布先へ進む、という流れの見た目を揃える。Android Widgetの収納と各Hatch固有の接続は別に実装する。

この再調査ではモック本体は変更せず、設計提案として記録した。

Androidでどこまでできるか

機能実現方法と境界
ホームの置き換えネイティブAndroidアプリをHOME候補として実装し、ユーザーが既定ホームとして選ぶ。HTML単体でAndroidのホーム機能は実現しない。RoleManager / ROLE_HOME
実フォルダをタブ化Storage Access Frameworkでユーザーが選んだフォルダのURIを保持。永続許可を取得して再起動後も復元する。フォルダ削除・移動や許可取り消しでは再選択を案内。Android 11以降では内部ストレージ直下、Download全体、Android/dataなどに制約があるため、Documents配下の作業フォルダを推奨する。Androidのファイルアクセス仕様
SD・クラウド端末で提供されるDocumentsProviderを経由して扱う。すべてのクラウドサービスがフォルダ選択を提供するとは限らない。SDの取り外し、オフライン、プロバイダー差は別途扱う。端末間同期はこの仕組みだけでは実現しない。
Widgetの収納AppWidgetHostを実装し、ユーザーの許可・必要な設定を経て配置。Widgetの最小サイズとリサイズ対応を守る。ドロワーの幅に合わない場合は全面で表示する。外部Widgetの配色や字体を完全に統一できるとは限らない。公式Widget Host仕様
メール・連絡先・予定初期版はアプリ起動と提供元Widget。独自一覧は、連絡先・予定の権限やメールサービスの認証など個別実装が必要。メールを任意のアプリから共通に取得する前提にはしない。Androidの共通Intent
LINEトークタブを開くURLと共有を使う。公開URL仕様を根拠に個人の全会話履歴や友だち一覧を取り込むことはできない。通常の個人トークを任意指定する保証も置かない。LINE公式URL仕様
端から引き出す初期版はホーム内で動作。タブを内側に寄せ、左右位置を変更可能にする。全アプリの上に常駐するDeskHatch風オーバーレイは、別権限・入力競合・端末ごとの挙動を伴う追加機能として切り分ける。
Hatchの導入登録された公式ストア・配布先へ案内。APKを扱う場合はOSの許可とインストール確認を通す。初回導入のサイレントインストールを前提にしない。PackageInstallerのユーザー確認

端末への広げ方

機種名ごとの固定画面ではなく、利用可能なウィンドウの幅と高さで構成を変える。これは折り畳み・回転・分割画面にも対応しやすい。AndroidのWindow size classes、Adaptive Appsの指針を根拠にした設計提案。

THETA.xxx.Hatchとの接続

既存HatchシリーズやDeskHatchのソース・仕様は、このチャットでは参照できていない。連携は次の契約を決めてから実装する。

  1. アプリごとの正式名称・対象OS・Androidパッケージ名を登録。
  2. 開く操作、受け取れるファイル形式、共有IntentやApp Linksの対応を明確化。Windows/Web版は対応するWeb入口や同期方法を設計。
  3. 導入済み判定に必要なパッケージを照会し、導入済みなら「開く」、未導入なら公式配布先へ。パッケージ可視性の宣言に従う。
  4. レイアウト設定は移行できるようにする。ただしフォルダURIのアクセス権は端末ごとに再取得する。設定移行とファイル同期を別に扱う。

実装の順番

  1. 触り心地を決める：今回のモックでQuiet / Studio、タブ位置、フォルダの開閉を評価。
  2. Z Fold5で最小実装：Kotlin＋Jetpack Composeを候補に、既定HOME、フォルダ登録・閲覧、外部アプリで開く・共有、アプリとブックマークのドロワー、状態保存まで。WidgetはAndroidView経由のAppWidgetHostで別途実装。
  3. 実用化：カレンダー・メールWidget、フォルダ許可の復旧、ファイル増加時の遅延読み込み、機種再起動・プロセス終了時の復元、権限拒否時の案内を確認。
  4. 展開：タブレットとTitan実機、Hatchシリーズ接続、必要なら公式配布カタログと更新導線。常駐オーバーレイは使い心地を見て追加。

実現可能性は高い。ただし「見た目を作る」より、ファイル権限・Widget・Fold開閉時の状態保持に検証工数がかかる。まずZ Fold5でフォルダ中心の最小版を成立させるのが、希望を保ちながら進めやすい。
