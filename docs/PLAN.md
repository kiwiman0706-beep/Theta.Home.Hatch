# 計画

## 核になる考え方（2026-10-23 の要望）

1. **背景（デスクトップ）はファイラー。** スマホはアプリへのアクセスは良いがファイルへのアクセスが悪い。PC のデスクトップのようにファイルの置き場をホームにする。散らかして置くのではなく、ファイラーとして置く。
2. **端のタブでドロワー・ウィジェットを切り替える。** スライドインする動きは残す。
3. **ファイラーから NAS へ行きやすく。** DSBooks のように Tailscale と NAS の接続状態を出し、つながっていなければ Tailscale を開く・再接続で助ける。
4. **ウィジェットは 1 タブ 1 つ。** 大きさを変えられる。フォルダブルは閉じたときと開いたときで別の設定。もう一方の画面の設定を持ってくるメニューも。

0.3.0-alpha で 1〜4 を一通り入れた。

## NAS と Tailscale（DSBooks の作りに合わせた点）

- DSM File Station API：`entry.cgi` で API を問い合わせ → `SYNO.API.Auth`（v3 まで、session=FileStation, format=sid）→ `SYNO.FileStation.List`（list_share / list）・`Download`。セッション切れ（105〜107・119）は 1 回だけログインし直す。
- Tailscale は外部アプリ（`com.tailscale.ipn`）として開くだけ。VPN の有無は `NetworkCapabilities.TRANSPORT_VPN`。届かない理由を「回線なし／VPN オフ／それ以外（NAS の電源・接続先）」に分けて案内する。

## 構想：wena 3 を Home から直接使う（2026-11-07、まだ作らない）

元の資料：利用者の調査メモ（Gadgetbridge の wena 3 実装。作者表記 akasaka / Genjitsu Labs、PR #3311、AGPL-3.0-or-later）。

**作り方の案**：Home に直接入れず、別アプリ「wena の連携」（AGPL で公開）に BLE を任せ、Home とは Intent・ContentProvider でつなぐ。AGPL のコードを Home に混ぜずに済み、BLE の常駐（Foreground Service・Companion Device）も分けられる。

**試し方**：wena を 2 台持っている。メインは今まで通り Gadgetbridge、もう 1 台で試す。接続先は MAC アドレスで固定し、メインには触らない。初期化で本体の設定を上書きしない。行けそうになったら切り替える。

| やりたいこと | 見込み | メモ |
| --- | --- | --- |
| 通知をフィルターして送る | ◎ | 通知の受け取りと NoticeRules はもうある。送るのは公開されたパケット |
| Gemini で要約して送る | ◎ | 本文の上限（Gadgetbridge は 239 に切っている）に収める。日本語は要確認 |
| 電池残量を出す・少ないと知らせる | ◎ | 電池の読み出しは実装あり |
| 活動・Body Energy をホームに出して貯める | ○ | 同期は実装あり（FW 2.40 以上）。睡眠は不安定と報告あり |
| アラーム | ○ | アラームの同期は実装あり。タイマーは「今＋N 分のアラーム」で代用 |
| ストップウォッチ・タイマーを本体で起動 | △ | 本体の画面を外から開けるかは不明 |
| 時計を探す（鳴らす） | △ | 専用の操作は対応一覧に無い。振動・LED つきの通知を送って代用 |
| ボタンでスマホを操作 | △ | 音楽・カメラは HID で届く。任意の操作を受け取れるかは要調査 |
| マイク（AI・録音） | ✕に近い | Alexa は非対応。BLE で音声を受け取る仕組みは公開されていない |
| PC（DeskHatch）と連動 | ○ | スマホが中継すれば、PC からの知らせを wena へ、は作れる |
| 電子マネー | 対象外 | QUICPay は本体だけで動くので触らない |

**ほかの使い道**：予定の数分前に振動・LED（予定のタブ）、NAS や回線が落ちたら知らせる、Hatch の更新が終わったら知らせる、MemoHatch の締め切り、天気の警報（Alerts）、色ごとの通知（LINE は緑など）、在宅・外出（Tailscale・Wi-Fi）で知らせる量を変える、腕を上げて点灯を夜は切る。
